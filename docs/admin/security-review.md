# Security review and advisor exceptions

Read-only inspection of the existing Supabase project found the foundation administrator policies and three applied migrations. Security advisor results retrieved on 2026-10-26 reported:

- Three `security_definer_view` errors for `travel_destinations`, `travel_attractions`, and `travel_photos`: https://supabase.com/docs/guides/database/database-linter?lint=0010_security_definer_view . These are intentional, separately reviewed owner-executed, security-barrier projections. Ordinary roles cannot read raw editorial rows, and the views explicitly allowlist fields and filter approved/published/reviewed parent/child content and photo rights. Changing to security_invoker without redesigning column grants/RLS would remove the public content API. Automated tests exercise both allowed and denied paths. This exception needs human security approval; the advisor has not been claimed clear.
- `rls_enabled_no_policy` info for `travel_private.admin_roles`: https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy . This is intentionally deny-by-default with no client table grants or membership self-assignment policy. The private fixed-search-path `is_admin()` function performs the minimal membership lookup.

The new migration adds one similarly allowlisted owner-executed view, `travel_photo_delivery`, exposing only published-safe photo IDs and object paths. Its expected advisor finding is documented here; it has not been inspected remotely because the migration has not been deployed. New public admin RPCs are SECURITY INVOKER, restricted to authenticated execution, and explicitly check database administrator membership. The private audit trigger is SECURITY DEFINER only to append immutable application-role history; it has an empty search_path and no client execute grant. Existing content RLS remains the write boundary.

The admin shell is a client-rendered app with no server-rendered private dataset. A route/page URL alone grants no data access. getUser verifies Auth sessions; no user_metadata authorization, signup promotion or client role field is used. Sessions are scoped to the admin browser tab. Mutations use bearer JWT Data API requests, not cookie-authenticated Next server actions. No service-role key or server secret is needed. React text rendering, safe HTTPS external links, noopener/noreferrer, raster-only uploads, security headers and CSP reduce injection risk. Inline hydration scripts/styles are still allowed for Next; a stricter nonce-based CSP is a future hardening step. No guarantee against XSS or legal compliance is made.

Publishing checks, permanent IDs, photo-placeholder preservation, approval invalidation, audit writes and version increments are database triggers, so raw API callers cannot bypass the form. CAS RPCs lock and compare the current version before modifying a record. Direct authenticated editorial table updates remain available to trusted admins under RLS and database guards; clients must use the RPC for optimistic concurrency guarantees. All non-admin writes remain denied. A future stronger RPC-only model would require a separate least-privilege API execution role and grant redesign, not adding an unrestricted definer RPC.

Storage policies are restricted to the dedicated private bucket. Public access is only through an approved and published photo/assignment projection. No UPDATE/upsert or delete policy is added for objects. Orphaned private uploads after failed/cancelled saves need a trusted retention/cleanup job; do not delete objects merely because a client reports failure. Check existing Storage policies for overlapping permissive grants before deployment. Re-run the advisor and hosted JWT/Storage tests in staging after applying the migration.

The Supabase skill documentation search confirmed signInWithPassword and private Storage access/signed URL behavior. The changelog HTTP fetch was unavailable under the environment's network policy; current docs were queried through the connected Supabase documentation tool. No remote migration, content publication, role assignment or Storage reconfiguration was performed.
